# UE5-17 — UE57Editor — Multiple Height Ranges with colors and overlap validation

**# UE57Editor — Multiple Height Ranges with colors and overlap validation**

**## Goal**

Расширить существующий инструмент ****Height Zone**** в \`LandscapeHeightmapTracker\`.

Сейчас пользователь может задать один диапазон:

\`\`\`text

Height Min

Height Max

\`\`\`

и отобразить его на 2D heightmap.

Необходимо добавить поддержку ****нескольких диапазонов высот****, каждому диапазону назначать свой цвет.

При этом ****пересечение диапазонов запрещено****.

**---**

**## UI**

Существующие поля оставить:

\`\`\`text

Height Min, m

Height Max, m

\`\`\`

Добавить:

\`\`\`text

Color: [ Cyan ▼ ]

[ + ]

\`\`\`

Кнопка \`+\` добавляет текущий диапазон в список.

Рядом или ниже разместить \`ListBox\`:

\`\`\`text

Height Ranges

[x] ■ 0 – 200 m

[x] ■ 200 – 600 m

[x] ■ 600 – 900 m

[x] ■ 900 – 1200 m

\`\`\`

Где:

\- \`[x]\` — включение/отключение диапазона;

\- \`■\` — выбранный цвет;

\- текст — Min/Max диапазона.

Добавить кнопки:

\`\`\`text

Remove

Clear All

\`\`\`

\`Remove\` удаляет выбранный диапазон.

\`Clear All\` удаляет все диапазоны.

**---**

**## Range data**

Использовать отдельную структуру, например:

\`\`\`cpp

struct FHeightRangeDefinition

{

&nbsp;&nbsp;&nbsp;&nbsp;double MinHeightMeters = 0.0;

&nbsp;&nbsp;&nbsp;&nbsp;double MaxHeightMeters = 0.0;

&nbsp;&nbsp;&nbsp;&nbsp;FLinearColor Color = FLinearColor::Cyan;

&nbsp;&nbsp;&nbsp;&nbsp;bool bEnabled = true;

};

\`\`\`

Коллекция:

\`\`\`cpp

TArray\<FHeightRangeDefinition\> HeightRanges;

\`\`\`

Не хранить эту информацию только внутри Slate ListBox.

UI должен отображать состояние модели, а не являться единственным источником данных.

**---**

**## Add Range**

При нажатии \`+\`:

1\. прочитать Height Min;

2\. прочитать Height Max;

3\. нормализовать:

\`\`\`cpp

Low  = FMath::Min(A, B);

High = FMath::Max(A, B);

\`\`\`

4\. проверить корректность;

5\. проверить пересечение с существующими диапазонами;

6\. если всё корректно — добавить диапазон;

7\. обновить ListBox;

8\. перестроить визуализацию.

**---**

**# Overlap validation**

**## Пересекающиеся диапазоны запрещены**

Пример существующего диапазона:

\`\`\`text

200 – 600 m

\`\`\`

Попытка добавить:

\`\`\`text

500 – 800 m

\`\`\`

должна быть отклонена.

Также отклонить:

\`\`\`text

100 – 300

300? → см. boundary rule ниже

400 – 500 внутри 200–600

100 – 700 полностью перекрывает 200–600

\`\`\`

**### Проверка overlap**

Использовать стандартную проверку интервалов:

\`\`\`cpp

bool bOverlap =

&nbsp;&nbsp;&nbsp;&nbsp;NewMin \< ExistingMax &&

&nbsp;&nbsp;&nbsp;&nbsp;NewMax \> ExistingMin;

\`\`\`

**---**

**## Boundary rule**

Соприкасающиеся границы ****разрешены****.

Допустимо:

\`\`\`text

0 – 200

200 – 600

600 – 900

\`\`\`

То есть:

\`\`\`text

Existing.Max == New.Min

\`\`\`

или

\`\`\`text

New.Max == Existing.Min

\`\`\`

не считается пересечением.

Это важно для создания непрерывных высотных поясов.

**---**

**# Overlap message**

Если пользователь пытается добавить пересекающийся диапазон, диапазон ****не добавлять****.

Показать стандартное Editor message dialog.

Пример:

\`\`\`text

Height Range Overlap

The range 500–800 m overlaps an existing range 200–600 m.

Height ranges cannot overlap.

Please choose a different minimum or maximum height.

\`\`\`

Кнопка:

\`\`\`text

OK

\`\`\`

Использовать стандартный Unreal Editor message dialog, например \`FMessageDialog\`, либо существующий аналог проекта.

Не использовать только лог или notification — пользователь должен явно увидеть сообщение.

**---**

**## Duplicate ranges**

Не разрешать точные дубликаты:

\`\`\`text

200–600

200–600

\`\`\`

Показывать аналогичное сообщение:

\`\`\`text

This height range already exists.

\`\`\`

**---**

**# Color selection**

Добавить ComboBox с набором заранее определённых цветов.

Например:

\`\`\`text

Cyan

Green

Yellow

Orange

Red

Blue

Purple

Magenta

\`\`\`

Каждое значение должно соответствовать \`FLinearColor\`.

Не нужно пока реализовывать полноценный Color Picker.

Цвет диапазона должен храниться вместе с диапазоном.

В ListBox желательно показывать небольшой цветной индикатор перед диапазоном.

**---**

**# Rendering**

Каждый enabled диапазон должен отображаться своим цветом.

Пример:

\`\`\`text

0–200 m       Cyan

200–600 m     Green

600–900 m     Yellow

900–1200 m    Orange

\`\`\`

На одной 2D heightmap одновременно должны отображаться все активные диапазоны.

Поскольку пересечения запрещены, смешивание цветов не требуется.

**---**

**## Mask generation**

Не создавать отдельную независимую систему вычисления высоты.

Использовать существующий:

\`\`\`cpp

HeightMetersCache

\`\`\`

Для каждого пикселя определить, принадлежит ли он одному из enabled ranges.

Пример:

\`\`\`cpp

for (const FHeightRangeDefinition& Range : HeightRanges)

{

&nbsp;&nbsp;&nbsp;&nbsp;if (!Range.bEnabled)

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;continue;

&nbsp;&nbsp;&nbsp;&nbsp;if (Height \>= Range.MinHeightMeters &&

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Height \<= Range.MaxHeightMeters)

&nbsp;&nbsp;&nbsp;&nbsp;{

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;// use Range.Color

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;break;

&nbsp;&nbsp;&nbsp;&nbsp;}

}

\`\`\`

Из-за запрета пересечений одна точка должна принадлежать максимум одному диапазону.

**---**

**# Boundary consistency**

Чтобы избежать визуального двойного попадания на общей границе:

\`\`\`text

0–200

200–600

\`\`\`

использовать единое правило включения границ.

Например:

\`\`\`text

Min inclusive

Max exclusive

\`\`\`

для всех диапазонов:

\`\`\`cpp

Height \>= Min && Height \< Max

\`\`\`

Для последнего/верхнего диапазона при необходимости допустимо включить Max.

Главное — использовать одно правило во всей реализации.

**---**

**# Contours**

Для каждого диапазона желательно отображать его границы существующим механизмом contour generation.

Например:

\`\`\`text

0–200:

&nbsp;&nbsp;&nbsp;&nbsp;contour 0

&nbsp;&nbsp;&nbsp;&nbsp;contour 200

200–600:

&nbsp;&nbsp;&nbsp;&nbsp;contour 200

&nbsp;&nbsp;&nbsp;&nbsp;contour 600

\`\`\`

Не генерировать одну и ту же общую границу дважды, если соседние диапазоны имеют одинаковую границу.

Это оптимизация, но желательно реализовать аккуратно.

**---**

**# Enable / Disable**

Каждая строка ListBox должна иметь checkbox.

Если диапазон отключён:

\`\`\`text

[ ] 600–900 m

\`\`\`

он:

\- остаётся в списке;

\- не участвует в overlay rendering;

\- не удаляется;

\- может быть снова включён без повторного ввода.

**---**

**# Remove**

\`Remove\` удаляет выбранный диапазон.

После удаления:

\- обновить ListBox;

\- обновить overlay;

\- обновить contours.

Если ничего не выбрано — кнопка должна быть disabled либо ничего не делать.

**---**

**# Clear All**

Удаляет все диапазоны и всю их визуализацию.

Не очищать:

\- Height Min;

\- Height Max;

\- выбранный Color;

если нет отдельной причины это делать.

**---**

**# Existing single Range behavior**

Не ломать текущую функциональность.

Существующие:

\- Height Min;

\- Height Max;

\- Range;

\- Apply;

\- Clear;

\- HeightMetersCache;

\- diagnostics;

\- Tracking;

\- Coordinate Diagnostics;

должны продолжать работать.

Если логично, текущий single Range режим можно внутренне перевести на новую коллекцию ranges, но без изменения поведения для пользователя.

**---**

**# Validation**

Перед добавлением диапазона проверить:

\- корректность числовых значений;

\- Min != Max;

\- диапазон пересекает существующий Landscape height range;

\- отсутствие overlap;

\- отсутствие duplicate.

Если:

\`\`\`text

Min == Max

\`\`\`

показать:

\`\`\`text

Invalid Height Range

Minimum and maximum height must be different.

\`\`\`

**---**

**# Suggested layout**

Пример:

\`\`\`text

Height Zone

Height Min, m    [ 200 ]

Height Max, m    [ 600 ]

Color            [ Green ▼ ] [ + ]

Height Ranges

┌────────────────────────────────┐

│ [x] ■   0 – 200 m              │

│ [x] ■ 200 – 600 m              │

│ [x] ■ 600 – 900 m              │

└────────────────────────────────┘

[ Remove ] [ Clear All ]

[ Apply ] [ Clear ]

\`\`\`

Не увеличивать окно без необходимости.

ListBox сделать компактным, желательно с ограниченной высотой и scroll при большом количестве диапазонов.

**---**

**# Sorting**

После добавления автоматически сортировать диапазоны по:

\`\`\`text

MinHeightMeters ascending

\`\`\`

То есть независимо от порядка добавления список должен выглядеть:

\`\`\`text

0–200

200–600

600–900

900–1200

\`\`\`

**---**

**# Important architecture requirement**

Multi-range результат должен быть пригоден для будущего использования не только UI.

Желательная цепочка:

\`\`\`text

HeightMetersCache

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;↓

HeightRanges

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;↓

HeightRangeGenerator

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;↓

MultiRangeResult

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;↓

 ┌──────────────┬──────────────┐

 ↓              ↓

2D overlay      future PCG

\`\`\`

Не связывать вычисление диапазонов напрямую со Slate rendering.

В будущем эта система будет использоваться для высотных зон растительности.

**---**

**# Non-goals**

В этом тикете не реализовывать:

\- PCG;

\- foliage placement;

\- смешивание цветов;

\- пересекающиеся диапазоны;

\- полноценный Color Picker;

\- сохранение диапазонов между проектами;

\- изменение Landscape Material;

\- Landscape Layers;

\- изменение геометрии Landscape.

**---**

\- [ ] Можно создать несколько диапазонов высоты.

\- [ ] Диапазоны автоматически сортируются по Min.

\- [ ] Для каждого диапазона можно выбрать цвет.

\- [ ] Цвет отображается в ListBox.

\- [ ] Все enabled ranges одновременно отображаются на heightmap.

\- [ ] У каждого диапазона свой цвет.

\- [ ] Checkbox временно отключает диапазон.

\- [ ] Remove удаляет выбранный диапазон.

\- [ ] Clear All удаляет все диапазоны.

\- [ ] Пересекающийся диапазон добавить нельзя.

\- [ ] В сообщении указаны оба конфликтующих диапазона.

\- [ ] Дубликаты запрещены.

\- [ ] Existing Height Zone behavior не сломан.

\- [ ] Tracking и Coordinate Diagnostics работают.

\- [ ] Overlay корректно перестраивается после добавления/удаления/enable-disable.

**# Manual tests**

**### Valid**

\`\`\`text

0–200

200–600

600–900

900–1200

\`\`\`

Все четыре диапазона должны быть добавлены.

**### Invalid overlap**

Имеется:

\`\`\`text

200–600

\`\`\`

Проверить:

\`\`\`text

500–800

100–300

300–500

100–700

\`\`\`

Каждый должен быть отклонён с message dialog.

**### Valid touching boundaries**

\`\`\`text

0–200

200–600

\`\`\`

должно быть разрешено.

**### Duplicate**

\`\`\`text

200–600

200–600

\`\`\`

Вторая попытка должна быть отклонена.

**### Colors**

Добавить:

\`\`\`text

0–200       Cyan

200–600     Green

600–900     Yellow

900–1200    Red

\`\`\`

На карте должны одновременно отображаться четыре однозначно различимые зоны.
