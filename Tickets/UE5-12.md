# UE57Editor — отображение высотных зон на 2D-карте Landscape

## Goal

Добавить в UE57Editor инструмент визуализации участков Landscape, соответствующих заданной абсолютной высоте.

Пользователь должен иметь возможность ввести высоту, например `800 м`, нажать кнопку **Применить** и увидеть на 2D-карте:

1. замкнутые контурные линии, проходящие по указанной высоте;
2. полупрозрачную высотную область, ограниченную этими линиями.

Инструмент в дальнейшем будет использоваться для выбора зон размещения растительности по высоте Landscape.

---

## User Interface

В панели управления 2D-картой добавить секцию:

### Height Zone

* числовое поле:
  * label: `Height, m`;
  * тип: `double` или `float`;
  * значение по умолчанию: `800`;
  * разрешить отрицательные значения;
* выпадающий список режима:
  * `Above` — области на указанной высоте и выше;
  * `Below` — области на указанной высоте и ниже;
  * `Contour Only` — только контурная линия;
* кнопка:
  * `Apply`;
* кнопка:
  * `Clear`;
* опционально:
  * настройка прозрачности заливки;
  * настройка толщины контурной линии.

После нажатия `Apply` карта должна обновляться без перезапуска окна.

---

## Required Behaviour

При значении:

```
Height = 800 m
Mode = Above
```

на 2D-карте должны отображаться все связные участки Landscape, высота которых равна или превышает 800 метров.

Каждый отдельный участок может состоять из:

* одного внешнего замкнутого контура;
* нескольких внутренних отверстий;
* нескольких полностью независимых высотных островов.

Необходимо корректно отображать все найденные области, а не только самую крупную.

Для режима `Below` должна выделяться территория с высотой меньше либо равной заданной.

Для режима `Contour Only` должна отображаться только изолиния заданной высоты без заливки.

---

## Height Coordinate System

Нельзя сравнивать введённые метры непосредственно со значениями пикселей heightmap.

Необходимо определить реальную высоту каждой точки Landscape через существующую систему преобразования UE57Editor.

Следует учитывать:

* высотные значения исходной heightmap;
* формат heightmap: 16-bit, 8-bit или используемый текущей реализацией;
* Landscape Z Scale;
* Landscape actor transform;
* возможное вертикальное смещение Landscape;
* минимальную и максимальную высоту исходных данных;
* существующую географическую привязку, если она уже реализована в проекте.

Нужно использовать один централизованный метод преобразования:

```
HeightmapValue -> UnrealLocalZ -> UnrealWorldZ -> HeightMeters
```

Не дублировать формулу пересчёта высоты непосредственно в UI или коде рендеринга.

Если UE57Editor уже содержит сервис преобразования координат Landscape и heightmap, расширить его, а не создавать параллельную реализацию.

---

## Contour Generation

Для построения изолиний использовать алгоритм **Marching Squares**.

Алгоритм должен работать по сетке высот 2D heightmap.

Для каждой ячейки из четырёх соседних значений необходимо определить пересечение пороговой высоты с её рёбрами.

Точки пересечения должны интерполироваться между пикселями, а не привязываться к ближайшему пикселю:

```
T = (TargetHeight - HeightA) / (HeightB - HeightA)
Intersection = PositionA + T * (PositionB - PositionA)
```

Это необходимо для получения плавного контура.

После построения отдельных сегментов:

1. соединить сегменты в полилинии;
2. соединить совместимые концы с учётом числовой погрешности;
3. сформировать замкнутые контуры;
4. корректно обрабатывать контуры, выходящие на границу карты;
5. удалить вырожденные и слишком короткие сегменты.

Для неоднозначных конфигураций Marching Squares использовать единообразное правило разрешения седловых случаев, например asymptotic decider либо сравнение со средним значением ячейки.

## Filled Region Rendering

В режимах `Above` и `Below` область должна иметь полупрозрачную заливку.

Предпочтительные варианты реализации:

### Primary option

Создавать бинарную маску размером с отображаемую heightmap:

```
Above: HeightMeters >= TargetHeight
Below: HeightMeters <= TargetHeight
```

После этого загружать маску как динамическую текстуру и накладывать её поверх 2D-карты.

### Contour overlay

Контуры рисовать отдельным Slate overlay поверх текстуры.

Не следует создавать отдельный Slate polygon widget для каждого пикселя или каждой ячейки: это плохо масштабируется на больших heightmap.

---

## Rendering Requirements

Высотная зона должна:

* совпадать с текущим масштабом 2D-карты;
* учитывать панорамирование;
* учитывать zoom;
* не смещаться относительно heightmap;
* не менять исходную текстуру карты;
* не повреждать существующие маркеры курсора и выбранных точек;
* отображаться под маркерами, но над основной картой.

Рекомендуемый порядок слоёв:

```
1. Heightmap texture
2. Height zone fill
3. Height contour lines
4. Hover marker
5. Selected point markers
6. UI annotations
```

При изменении размера окна или масштаба карты контуры должны оставаться синхронизированными с изображением.

---

## State

Состояние инструмента должно хранить:

```
struct FHeightZoneSettings
{
    double TargetHeightMeters;
    EHeightZoneMode Mode;
    float FillOpacity;
    float ContourThickness;
    bool bEnabled;
};
```

Пример enum:

```
enum class EHeightZoneMode : uint8
{
    Above,
    Below,
    ContourOnly
};
```

После `Clear`:

* удалить заливку;
* удалить контуры;
* сохранить введённое значение высоты либо сбросить его только при наличии отдельной команды reset;
* не затрагивать остальные элементы карты.

---

## Performance

Не пересчитывать высоты всех пикселей при каждом кадре.

При загрузке Landscape или heightmap создать кэш высот в метрах:

```
TArray<float> HeightMetersCache;
```

Перестраивать кэш только при изменении:

* Landscape;
* исходной heightmap;
* Landscape Z Scale;
* transform Landscape;
* параметров вертикальной геопривязки.

При нажатии `Apply` использовать готовый кэш.

Тяжёлые вычисления Marching Squares и бинарной маски не выполнять внутри `OnPaint`.

`OnPaint` должен только отображать заранее подготовленные данные.

Для больших heightmap рассмотреть выполнение расчёта в worker thread с безопасной передачей готового результата обратно в game/editor thread.

---

## Validation

Поле высоты должно проверяться перед применением.

Обработать случаи:

* значение отсутствует;
* введено некорректное число;
* высота ниже минимальной высоты Landscape;
* высота выше максимальной высоты Landscape;
* heightmap не загружена;
* Landscape не выбран;
* данные высоты ещё не инициализированы.

Если высота находится вне диапазона Landscape, показать понятное сообщение:

```
The selected height is outside the Landscape range.
Landscape range: 412.3 m – 1268.7 m.
```

Не считать отсутствие найденного контура ошибкой приложения.

---

## Architecture

Разделить реализацию минимум на три части:

### Height data

Отвечает за:

* извлечение высот Landscape;
* преобразование значений в метры;
* кэш высот;
* определение минимальной и максимальной высоты.

### Height zone generation

Отвечает за:

* threshold mask;
* Marching Squares;
* объединение сегментов;
* формирование замкнутых контуров.

### 2D map rendering

Отвечает только за:

* вывод маски;
* вывод линий;
* масштабирование;
* преобразование координат карты в экранные координаты.

UI не должен содержать алгоритм генерации контуров.

---

## Suggested Types

Пример результата вычисления:

```
struct FHeightContour
{
    TArray<FVector2D> Points;
    bool bClosed = false;
};

struct FHeightZoneResult
{
    double TargetHeightMeters = 0.0;
    int32 Width = 0;
    int32 Height = 0;

    TArray<uint8> Mask;
    TArray<FHeightContour> Contours;
};
```

Координаты контуров желательно хранить в нормализованном пространстве карты:

```
X: 0.0–1.0
Y: 0.0–1.0
```

Это упростит отображение при изменении размера карты и zoom.

## Acceptance Criteria

* В интерфейсе присутствует поле `Height, m`.
* Присутствуют кнопки `Apply` и `Clear`.
* Пользователь может ввести значение `800`.
* После нажатия `Apply` на 2D-карте появляется корректная высотная зона.
* Режим `Above` выделяет участки выше заданной высоты.
* Режим `Below` выделяет участки ниже заданной высоты.
* Режим `Contour Only` отображает только изолинию.
* Независимые высотные острова отображаются отдельно.
* Внутренние отверстия областей не заливаются ошибочно.
* Контуры совпадают с визуальной heightmap.
* Zoom и pan не нарушают совмещение слоёв.
* `Clear` полностью удаляет визуализацию зоны.
* Существующий hover-marker и выбранные точки продолжают работать.
* Высота рассчитывается в реальных метрах, а не в значениях пикселей.
* Расчёт не выполняется каждый кадр.
* Для тестовой синтетической карты результат можно проверить автоматически.

## Tests

### Unit tests

Создать синтетические сетки высот и проверить Marching Squares:

 1. полностью плоская карта ниже порога;
 2. полностью плоская карта выше порога;
 3. одиночный холм;
 4. одиночная впадина;
 5. два независимых холма;
 6. кольцевой рельеф с внутренним отверстием;
 7. контур, пересекающий границу карты;
 8. седловая конфигурация;
 9. порог точно совпадает со значением вершины;
10. отрицательные высоты.

Проверять:

* количество контуров;
* замкнутость;
* отсутствие разрывов;
* корректность маски;
* отсутствие NaN и бесконечных координат.

### Manual tests

 1. Открыть реальную Landscape heightmap.
 2. Ввести высоту в середине диапазона Landscape.
 3. Применить режим `Above`.
 4. Сравнить выделенные вершины с Landscape viewport.
 5. Проверить `Below`.
 6. Проверить `Contour Only`.
 7. Изменить zoom.
 8. Выполнить pan.
 9. Изменить размер окна.
10. Нажать `Clear`.
11. Проверить работу hover-marker.
12. Проверить работу выбранных точек.

## Non-Goals

В рамках этого тикета не реализовывать:

* автоматическую рассадку растений;
* генерацию Procedural Foliage Volume;
* изменение самого Landscape;
* экспорт маски в Landscape Layer;
* редактирование контура вручную;
* одновременное отображение нескольких высотных диапазонов;
* сохранение зон между сессиями;
* построение полного набора топографических горизонталей.

Эти возможности должны быть возможны как последующее расширение.

---

## Future Extension

Архитектура должна позволить позднее добавить диапазон высот:

```
Minimum height: 650 m
Maximum height: 900 m
```

И использовать полученную маску для:

* размещения растительности;
* ограничения пород деревьев;
* выбора альпийской или лесной зоны;
* Landscape Grass Output;
* Procedural Foliage;
* PCG Graph;
* экспорта маски;
* комбинирования с уклоном, влажностью и типом почвы.

Не связывать текущую реализацию напрямую с конкретным foliage-инструментом.

---

## Preflight

Перед изменениями:

1. изучить текущую архитектуру UE57Editor;
2. определить существующий источник данных heightmap;
3. найти текущий код преобразования координат между Landscape и 2D-картой;
4. проверить актуальность Graphify database;
5. проверить актуальность code-review-graph database;
6. обновить базы при необходимости;
7. найти существующие Slate widgets и overlay rendering path;
8. не создавать дублирующую систему координат или пересчёта высоты.

После реализации подготовить:

* список изменённых файлов;
* описание архитектурного решения;
* формулу преобразования высоты в метры;
* результаты unit tests;
* результаты ручной проверки;
* известные ограничения.
