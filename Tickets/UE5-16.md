# UE5-16 — Height Zone Range и визуализация диапазона высот на Landscape

Источник: https://bodomus.youtrack.cloud/issue/UE5-16

## Goal

Расширить существующий инструмент Height Zone второй высотой и режимом `Range`,
чтобы пользователь мог выделять точки Landscape в нормализованном диапазоне:

```cpp
Low = FMath::Min(HeightA, HeightB);
High = FMath::Max(HeightA, HeightB);
HeightMeters >= Low && HeightMeters <= High;
```

Все существующие режимы `Above`, `Below` и `Contour Only` должны сохранить
текущее поведение.

## UI

В секции Height Zone добавить:

- `Height Min, m` (пример: 600);
- `Height Max, m` (пример: 800);
- режим `Range` в существующий список;
- существующие кнопки `Apply` и `Clear` оставить без изменения назначения.

Для `Above`, `Below` и `Contour Only` используется основная высота. Для `Range`
используются оба значения. Обратный ввод `800 / 600` автоматически нормализуется
в `600 / 800` и не считается ошибкой.

## 2D Heightmap visualization

- Использовать существующий overlay/mask механизм Height Zone и существующий
  `HeightMetersCache`.
- Не изменять оригинальную heightmap texture.
- Диапазон должен иметь отдельный заметный полупрозрачный цвет.
- Строить и отображать обе граничные изолинии: Min и Max.
- Корректно поддержать несколько независимых зон, острова, отверстия и зоны,
  пересекающие границу heightmap.
- Не нарушить zoom, pan, Landscape ↔ Heightmap mapping, Tracking, markers и
  Coordinate Diagnostics.
- `Clear` полностью удаляет Range visualization.

## 3D Landscape visualization

Исследовать безопасный editor-only способ показать ту же зону на 3D Landscape.
Подсветка не должна менять Landscape Material, Landscape Layers, weightmap,
heightmap, geometry или сохраняться в asset. Она должна удаляться по `Clear`, при
закрытии окна и перед повторным `Apply`.

Предпочтительны editor viewport overlay, debug rendering, scene/view extension
или editor visualization component. Нельзя создавать тысячи Actors/Components
или отдельный объект для каждой точки.

Если качественная 3D-подсветка требует опасного вмешательства в rendering или
material pipeline, обязательна полная реализация 2D Range, подготовка reusable
data/result interface и обоснованный перенос 3D overlay в следующий тикет.

## Data model and architecture

Расширить существующие настройки и enum, не создавать параллельную реализацию:

```cpp
struct FHeightZoneSettings
{
    double HeightAMeters;
    double HeightBMeters;
    EHeightZoneMode Mode;
    float FillOpacity;
    float ContourThickness;
    bool bEnabled;
};

enum class EHeightZoneMode : uint8
{
    Above,
    Below,
    ContourOnly,
    Range
};
```

Range mask должна быть частью UI-independent reusable результата, пригодного для
будущих 2D/3D consumers, PCG, foliage filtering и экспорта:

```text
HeightMetersCache → HeightZoneGenerator → FHeightZoneResult
                                      ├→ 2D Overlay
                                      └→ 3D Editor Overlay
```

В этом тикете не реализовывать foliage, PCG, Landscape Grass Output, изменение
Landscape Material/Layers, экспорт, сохранение зон или несколько одновременных
диапазонов.

## Acceptance Criteria

- [ ] Добавлено второе поле высоты и режим `Range`.
- [ ] Значения `600 / 800` выделяют только зону 600–800 м.
- [ ] Range имеет визуально отличимый цвет.
- [ ] Отображаются или могут отображаться обе граничные изолинии.
- [ ] Независимые зоны, острова, отверстия и граничные зоны корректны.
- [ ] `800 / 600` даёт тот же результат, что `600 / 800`.
- [ ] `Clear` полностью удаляет Range visualization.
- [ ] `Above`, `Below` и `Contour Only` продолжают работать.
- [ ] Tracking, markers и Coordinate Diagnostics не сломаны.
- [ ] Расчёты используют существующий height cache.
- [ ] Range result отделён от UI и пригоден для дальнейшего использования.
- [ ] Исследована возможность 3D Landscape visualization.
- [ ] Реализованная 3D visualization (если есть) является editor-only и не
  изменяет Landscape assets.

## Manual Test

Проверить диапазоны `200–400`, `400–600`, `600–800`, `800–1000` м и убедиться,
что выделение последовательно перемещается вверх по рельефу. Сравнить результаты
`800–600` и `600–800`. При наличии 3D visualization проверить синхронность 2D/3D.

## Codex report

После реализации предоставить изменённые файлы, архитектуру Range Mode, способ
построения Range mask и двух контуров, решение по 3D visualization, результаты
build/tests и manual test.
